# Dataset-Adaptive Profiler 预验证实验设计（零 API）

## 研究问题

不同特征的表格（大/小、宽/窄、高缺失、高重复率）下，三种 profiler 策略在"重要源事实保留"上是否存在**交叉现象**（不同表类型的最优策略不同）？

## 实验单位与数据

- 从 subset30（seed=9 已冻结）按**事先确定的特征规则**选 14 张表：
  - 小表（≤100 行）3、中表（100-10k）3、大表（>10k）3
  - 宽表（≥40 列）2、高缺失（任一列缺失 >30%）2、高类别重复（某类别列 unique<10 且 n>1k）1
  - 特征规则先写死（本文件），再跑选择脚本，选中清单 SHA256 记录后冻结；不允许看了 profile 结果再换表

## Ground-truth 事实清单（先于一切 profile 建立）

对每张表，直接从原始 CSV 用独立脚本提取并人工可核验的原子事实：
- 行数、列数、每列 dtype、数值列 min/max（不含哨兵值处理）、缺失率、unique 数
- 时间列实际范围、类别列 top-3 频次、主键候选唯一性
- 关系事实：至少 2 条可验证的列间关系（如 A=B 映射、B≥A、复合唯一）
清单脚本 + 输出 JSON + 每表事实数记录，SHA256 冻结。**禁止**参考任何 profiler 输出。

## 三臂（同表示模板、近等 token 预算；P0 长度单报）

- **P0 忠实复现**：AutoDDG 原 Profiler（Content 统计 + Semantic 顺序采样 100 行）——输出表示同模板
- **P1 固定简单**：固定规则统计（dtype、min/max、缺失率、unique、top-3）+ 头部 5 行采样；按模板渲染
- **P2 最小信息增强**：P1 基础上加 (a) 分位表（5/25/50/75/95）替换 min-max、(b) 数值-类别分组的组内范围（最多 3 组）、(c) 一条检测到的列间关系
- Token 预算：P1 与 P2 渲染后字符差 ≤15%（超则截尾并记录）；P0 实际长度单独报告不强制对齐

## 评价（无 LLM，全部程序判定 + 人工抽查）

每臂输出 vs ground-truth 清单：
1. **正确保留数**（数值在容差内一致）
2. **遗漏数**（清单有、臂输出无）
3. **失真数**（数值超出容差/语义改变——如未处理的哨兵值 min=0、范围截断）
4. **关系保留**（P2 的关系是否正确、P0/P1 是否碰巧包含）
5. **Token 成本**（渲染字符数/估算 token）

主分析：**按表特征分层**（6 组）看策略×特征的交叉——每组内三臂排名是否翻转；交叉显著性用逐表配对差的符号检验（n 小，只做描述性）。典型失败案例：每臂×每组至少 1 例，摘录原文。
