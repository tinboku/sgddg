# C05 Structure-Preserving Context Representation：最小 paired diagnostic（2026-10-22）

> 筛选阶段的质量对照，不是检索实验；不算 NDCG。n=12、单次运行、T=0，属于 feasibility 证据，不做显著性结论。
> 文中"核对"由 Claude 逐条完成，**不是人工评价**；人工盲评表见 `results/c05/blind_sheet_ufd.md`（答案在 `blind_key.json`）。

## 1. 假设

CANDIDATES C05：Profile 的序列化方式会影响 LLM 把事实关联到哪一列，也影响输入 token。
**H：** 在信息量完全相同的前提下，按列分组的紧凑键值表示能更好地保留列—事实对应关系（列混淆更少、忠实性更高），且成本更低。
**停止判据：** 如果只是格式更短，没有实质的机制或质量效应，就停止。

## 2. 两臂设计（只换表示形式）

| | 原版（orig） | 结构化（struct） |
|---|---|---|
| 来源 | F2/r1 缓存，原样复用 | 同一份 F2/r1 缓存 |
| 样本、topic、semantic profile、factset、所选事实 | 相同 | 相同（逐字节） |
| UFD prompt 模板、gpt-4o-mini、T=0、run_id r1、100 词预算 | 相同 | 相同 |
| UFD profile 槽 | AutoDDG 自然语言 basic profile | 按列分组的键值块：`[列]` 下分 `profile:` / `semantic:` / `facts:`，另设 TABLE 组放表级事实；≥40 字符的共享值走 VALUES 字典引用 |
| UFD semantic 槽、facts 槽 | 原文 | 改为一句指针（"见上方结构化 profile 的 semantic / facts 项"） |
| SFD facts 槽 | `- Slot: col: fact; …` | 同样的事实，按 TABLE + 列分组 |

- 原版臂经由同一套生成代码重跑：12/12 张表的 UFD/SFD prompt 和输出都与 F2/r1 缓存逐字节一致（全部命中缓存），说明基线没有漂移。
- **信息等价（逐列覆盖）**：`c05_structured.check_lossless` 逐列核对原文每行（basic、structural、semantic、每条事实）里的数字和取值词，要求它们都出现在该列的块里。UFD 12/12 表缺失 0/1934 个原子，SFD 缺失 0/868。也就是说，每列的统计量在两种表示里都出现了。
- 原文本身就有来源冲突：profile 的范围来自样本（datamart），事实来自全表，例如 4b5bd984 Date Created 一个是 2019-01-02~2023-03-06，一个是 2019-01-01~2026-10-20。结构化表示用 `profile` / `facts` 键保留了来源，没有合并。

## 5. 列混淆与忠实性（Claude 逐条核对，非人工）

做法：从 UFD/SFD 里抽出所有数字（≥32 或带小数），在逐列证据（该列的 profile、semantic、facts 以及样本取值）中查找支持它的列，再与句中点名的列比对，标出"候选列混淆"和"无依据"（`results/c05/number_audit.json`）。之后对 UFD 的全部 24 篇逐句通读。

- 自动候选：UFD 中原版 10 条、结构化 8 条。逐条核对后，**全部都是假阳性**：要么句中的普通词与列名同形（Utility、Status、Filing），要么是 SFD 中多列事实写在同一行。

## 7. 失败案例与局限

1. **格式泄漏**：结构化输入下，9/12 篇 UFD（另 1 篇擦边）把 100 词预算的一部分花在描述"semantic/structured profile"上，挤掉了事实（事实保留从 33 降到 25）。
2. **来源混用**：同一列块里并列 `profile` 范围（样本）和 `facts` 范围（全表）后，模型在 3 张表里选了样本范围。原版把事实放在 prompt 末尾的独立段，并紧跟"必须用这些名称/年份"的指令，模型都选对了。按列共置似乎**削弱了**"事实优先"这条指令的约束力。
3. **混杂**：结构化臂把三段证据合进 profile 槽，semantic/facts 槽改成指针，所以"表示形式"和"事实在 prompt 中的位置"是一起变的。这是按列分组时绕不开的混杂，没有做位置对齐或 token 对齐的对照臂。
4. 只测了一种结构化格式、一次运行、12 张表，自动核对规则只覆盖数字。

## 8. 结论（按 C05 停止判据）

- **成本：** 只是"略短"。全流程 token 降 0.4%，UFD 输入降 1.4%，费用差约 $0.0002/12 表，没有实际意义。
- **质量：** 没有观察到正效应，方向反而偏负：
  - 原版臂本身没有列混淆（0 例），所以 C05 想修的基线问题在这 12 张表上很少见；
  - 结构化臂的事实保留更低（25 vs 33），来源混用更多（3 vs 0 表，其中 1 表为跨列拼接），格式泄漏 9/12。
- **判定：按停止判据，C05（这种形式）建议停止或降级。** 不建议扩大规模；它的结果可以作为失败分析写进论文："在 AutoDDG 中样本占主导的 prompt 里，profile 序列化不是瓶颈，按列共置还可能削弱事实优先指令"。
- 如果研究者仍想保留 C05，唯一值得做的补充是位置对齐对照：只在原 facts 槽内按列分组，profile/semantic 保持原样。这样能分开"表示形式"和"位置"两个因素。这需要研究者批准。

## 10. 位置对齐对照（2026-10-22 追加）

> 回应 Codex 审查：结构化臂同时改了表示形式、事实位置（prompt 末尾 → profile 槽）和指针措辞，归因不纯；只改 facts 槽也不够，要隔离整个 profile 处理。

### 10.1 设计

新增第三臂 **pos**（`c05_pos_run.py`，序列化函数 `c05_structured.aligned_*`）：

- 三个证据槽（basic profile 槽、semantic 槽、facts 槽）**各留在原版位置**，槽前后的指令文字不变；
- 每个槽内，只把"按列的自然语言句子"改写成"按列分组的 key=value 行"（`[列]` 一行，下一行写 `type=…; unique_values=…; coverage=…`）。facts 槽同样按 TABLE + 列分组，用 ` | ` 分隔；
- 不用指针句、不加结构说明头、不用 source 键（每个槽只有一个来源）、不用 VALUES 字典。槽内的非列行（"The key data profile information…" 等）原样保留；
- SFD 的 facts 槽使用同一种分组文本。

**结构同构检查（每表断言）**：把三个槽的内容挖掉后，pos 和 orig 的 UFD prompt 逐字节相同；SFD prompt 挖掉 UFD 原文和 facts 槽后也逐字节相同。12/12 通过。
**信息等价**：三个槽合起来做逐列无损检查，UFD 缺失 0/1934，SFD 缺失 0/868。原版的 slot 标题（Identity / Temporal scope…）在按列分组后不再出现，这是分组本身的结果；标题词属于检查里的样板词。

模型、T=0、run_id r1、样本、topic、semantic profile、factset 与前两臂完全相同。pos 臂 24 次调用全部是新调用。

### 10.3 解读

1. **结构化臂的主要负效应来自"共置 + 指针/说明头"，不是 key=value 表示本身。** 位置固定后，格式泄漏从 9/12 降到 0/12，事实保留从 25 回到 30，样本范围压过事实从 3 表降到 2 表（其中 4b5bd984 已改用全表范围）。
2. **但只换表示形式也没有正效应。** 相对原版：事实保留 30 vs 33（−3，12 表单次运行，属于噪声量级，不能判为显著变差），SFD 106 vs 108，列混淆和来源混用反而各多 1–2 例（原版两项都是 0）。UFD 输入只降 1.8%（每表约 150 tok），原因同前：prompt 主体是 100 行样本。
3. 原版臂在这 12 张表上本来就几乎不出列混淆，所以 C05 想修的问题在当前 prompt 里没有出现到可以被改善的程度。

### 10.4 结论更新

- 归因已分离：**表示形式本身 ≈ 中性偏负、成本几乎不变；初版的明显负效应主要是位置/指针造成的。**
- 按 C05 停止判据（"只是格式更短，没有实质的机制或质量效应就停止"），**结论维持：停止 / 降级**，理由从"表示形式有害"改为"表示形式无益"。不建议扩大规模。
- 本节 API 新增花费 **$0.0213**（pos 臂 24 次调用；gpt-4o-mini）。
