# 方向③ 同预算采样（Distribution-Aware Semantic Sampling）最小实验简报

日期：2026-10-22　范围：subset30（29 张可用表 / 697 列；fbb92a2a 原本即因上下文超长失败，三组一致排除）
模型：gpt-4o-mini，T=0，走 LLM 缓存

## 一句话
采样策略**确实改变了语义标签**（变化率 49–61%，噪声底 23–29%），但**描述（UFD/SFD）层面与噪声不可区分**，长尾值、频率说法、忠实性、重要事实遗漏四项程序化检查三组无差别。按任务书判据：**只有输入形式和中间标签变化，描述基本不变 → 不再扩大。**

## 设计
只改 SemanticProfiler 每列看到的 5 个值，其余（topic、100 行数据样本、basic/structural profile、UFD/SFD prompt）全部复用 bugfix 臂。

| 组 | 每列 5 个值 |
|---|---|
| orig | AutoDDG 原样：100 行样本中再随机 5 行（random_state=9）|
| freq | 全列最高频 5 值，带频数 `value (n=count)` |
| dist | 全列、可解释、不训练：数值列取 min/25/50/75/max 对应真实单元格；混合格式列每种格式 1 例（profiling_v2.stats.value_format，≥2 种占比 ≥5% 且含数字的形状）后补高频；其余类别列高频 3 + 最稀有 2；≤5 个不同值的列取全部 |

dist 的列分布：分位 268、头3+尾2 177、混合格式 140、小值域 99、全空 13（全空列三组输入相同）。
正确性检查：orig 通路逐字复现 bugfix r1（29/29 张表 topic/语义/UFD/SFD/UFD prompt 全同，100% 命中缓存）。
复跑：三组各做 r2（topic 固定取 r1，只复跑 语义→UFD→SFD），用来量 T=0 下的噪声底。

脚本：`02_generate_sampling.py`（生成）、`06_sampling_analysis.py`（检查）；结果 `results/sampling/s3_analysis.json`。

## 验证结果（全部程序化，无 LLM judge）

### 1. 语义识别变化（列级，5 个字段任一不同即算变化）
| 对比 | r1 | r2 |
|---|---|---|
| orig vs freq | 411/697（59.0%）| 423/697（60.7%）|
| orig vs dist | 341/697（48.9%）| 357/697（51.2%）|
| freq vs dist | 395/697（56.7%）| 374/697（53.7%）|
| **噪声底**（同组 r1 vs r2）| orig 23.4% / freq 26.0% / dist 28.7% | |

复杂分布列（重尾数值 / 长尾类别 / 混合格式，478 列）：orig vs dist 239–260 列变化，噪声底 107–144。
→ 策略效应约为噪声的 2 倍，**标签变化是真实的**。但没有列语义的金标准，**"变了"不等于"变好"**，本实验无法证明改善。变化主要落在 usage context 和 entity type 这类自由文本字段，temporal/spatial 布尔判断变化小（34–46 列，噪声 11–35）。

### 2. 少数模式识别（类别列 n_distinct>5、非主键，303 列）
| | orig | freq | dist |
|---|---|---|---|
| 样本含 top-5 之外的值 | 187 | 0 | 201 |
| 长尾值出现在语义说明 / UFD / SFD | 2 / 0 / 0 | 0 / 0 / 0 | 0 / 0 / 0 |

→ 随机 5 行本来就常常抽到长尾（187/303），dist 只多 14 列；freq 完全丢失长尾（符合预期）。**三组都没有长尾值进入描述**。

### 3. 频率理解
UFD/SFD 中含 "most common / mostly / majority / predominantly…" 且点名类别值的句子：**三组、两轮全部为 0**。此项无法比较——描述本身不做频率断言。

### 4. 忠实性 / 完整性（05_fact_audit 口径）
| | orig r1/r2 | freq r1/r2 | dist r1/r2 |
|---|---|---|---|
| UFD 无支持数字 | 3/81、1/85 | 3/92、4/86 | 4/89、2/89 |
| SFD 无支持数字 | 0 | 0 | 0 |
| 重要事实遗漏（F1 verified 的 table_size/temporal_span/spatial_places，共 84 条）UFD | 76、74 | 72、76 | 75、74 |

→ 全部落在噪声范围内（orig 自身两轮就差 2）。
UFD 逐字相同的表数：跨组 1–4/29，同组复跑也只有 2–3/29——**UFD 文本差异与复跑噪声同量级**。

### 5. Token 与成本
| | 语义阶段输入 + 输出 token（每轮）| 相对 orig |
|---|---|---|
| orig | 318,170 + 45,744 | — |
| freq | 333,960 + 46,621 | 输入 +5.0%（频数标注）|
| dist | 320,323 + 46,399 | 输入 +0.7% |

实际新调用花费：freq r1 $0.132、dist r1 $0.128、orig r2 $0.131、freq r2 $0.132、dist r2 $0.127，**合计 ≈ $0.65**（预算 $2；跑前估算 ≈ $0.75）。orig r1 全部命中缓存，$0。

## 为什么描述不变（机制，非推测：来自 AutoDDG 代码路径）
1. 5 个样本值只进 SemanticProfiler；它的输出被 `_create_column_summary` 压成 "Represents X. Domain-specific type: Y. Function/Usage context: Z." 这种泛化短句，样本值本身不进 UFD。
2. UFD prompt 里还有一份 100 行数据样本（三组完全相同），信息量远大于语义短句，主导了描述内容。
3. 所以采样只能通过"换几个标签词"影响 UFD，这个通道太窄，效果淹没在 T=0 的复跑噪声里。

## 按任务书判据的结论
- 判据"语义识别和描述有可重复改善（尤其复杂分布列）"：语义标签有可重复**变化**（两轮一致，约 2 倍噪声），但无金标准证明是改善；描述层面无可测差异。**不满足。**
- 判据"只有输入形式变化、语义判断和描述基本不变 → 不再扩大"：语义判断有变化，但描述基本不变，最终产物上属于这一档。
- **结论：不再扩大③。** 若以后还想做，前提是改通道（让样本或分布摘要直接进 UFD），那已经不是"只改样本选择"，属于④/A 的事实注入路线，那边已有负/中性结果。

## 局限（如实）
- 列语义没有金标准，"变化"无法定性为好坏；若要判断，需要人工标注一部分列（未做）。
- 频率检查样本为 0，该项无结论。
- freq 组带频数，同时改了"选什么"和"怎么写"，两者混在一起；dist 保持原样纯值格式，只改选择。
- 只有 29 表 × 2 轮。
