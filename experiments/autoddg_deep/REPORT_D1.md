# D1：辨别式 SFD 生成（#5 最小原型，subset30）

状态：实验完成。结论为负：改生成目标在 30 表 BM25 上同样无增益。

## 实现

- AutoDDG 仓库只新增 `description/search_discriminative.py`（`DiscriminativeSearchDescription`，继承 `FactAwareSearchDescription`），原包文件不改。
- prompt = F2 的 SFD prompt 原样 + 两处插入：
  1. template 指令前插入"易混淆邻表"块（邻表标题 + F2 UFD + SFD 事实，标明"仅供对比，不属于本表"），要求说明"为什么选本表而不是它"，优先写能区分两表的真实属性（观测单位/时间范围/粒度/地域/度量/类别）；
  2. template 在 Verified Coverage 之后加 "Distinguishing Characteristics" 段。
  - 红线规则写进 prompt：硬事实只能来自本表描述与事实；不许抄邻表独有的词/名/值，不许描述邻表，不许列本表缺什么；本表内容的同义/联想照常允许。
- 运行时断言：去掉两处插入后的 prompt 与 F2 缓存的 `sfd_prompt` 逐字相同（29 表全过）。profile/事实/topic/UFD 全部读 F2/r1 缓存，只发 SFD 调用，每表 1 次，T=0。
- 等长：输出截到该表 F2 SFD 的 whitespace 词数。28 表截断（模型输出 330–516 词），1 表（19610d2e）短 19 词，记为 `discriminative_length_delta=-19`，未报错。
- fbb92a2a（宽表）在 F2 已失败，D1 继承失败与原描述回退，同前。
- 新文件（实验仓库）：`01b_confusion_pairs.py`、`02_generate_discriminative.py`、`06_discrimination.py`、`configs/arm_D1.yaml`、`configs/confusion_pairs.{txt,json}`、`run_d1.sh`。`arm_D1.yaml` 除 `arm` 和 `discriminative_sfd` 外与 `arm_F2.yaml` 相同（脚本断言）。

## 混淆对

规则：用每表 bugfix 文档（标题+SFD）做 BM25 查询，检索另外 29 表；候选按 qrels 分层，取最高非空层里 BM25 最高的一张：
- 层 2：两表对某查询同为正例；层 1：两表对某查询都有判断且至少一个正例；层 0：无共同判断（纯 BM25）。

30 表的邻表：层 2 = 5 表、层 1 = 6 表、层 0 = 19 表；8 表的邻表因 qrels 分层而不同于纯 BM25 top-1。

## 红线检查（本地）

- 29 表都生成了 Distinguishing Characteristics 段。
- 无支持数字（不在本表 F2 prompt 中的数字，邻表块不算依据）：D1 3 表各 1 个（2a3cc123 "45"、62acddae "17"、f359e457 "11"）；F2 为 0。
- 邻表独有词（出现在 SFD、不在本表 prompt、但在邻表文本里）：D1 137 个 vs F2 104 个（F2 的数值是巧合基线）。D1 多出的大多是通用词（each/providing/geographic），但有若干实词需人工核：2f1aabc5 的 dispatch/arrival/timestamps、19610d2e 的 eviction/districts、14f56ea0 的 lobbying、be2a86f4 的 gravesite、e83c4ac6 的 genealogical。其中可能有表里确有但输入未给出的内容，也可能是泄漏；无论哪种，都不受本表输入支持。
- 3 表违反"不许描述邻表"（14f56ea0 写了 "unlike broader lobbying expenditure datasets"、53acdac4 写了 "Unlike datasets with limited temporal scope"；4b5bd984 的 "other datasets" 属通用句，算误报）。
- 结论：prompt 级红线约束有效但不严密，约 10% 的表出现了硬事实或邻表词泄漏；若继续做，需要程序化过滤（同 Q1 的证据过滤）。

## 成本

- D1 SFD：29 次 gpt-4o-mini 调用（无缓存命中），prompt 44,088 token + completion 18,936 token，按 $0.15/$0.60 每百万 token 计 **≈ $0.018**。
- 混淆对、评测、辨别率、审计均为本地计算，无 API 消耗。总消耗远低于 $0.5 上限。

## 结论

1. **改生成目标没有绕开文本层不敏感**。D1 的 SFD 文本相对 F2 改动不小（词集 Jaccard 中位 0.60，即约 40% 的词换了），但 25 个查询中只有 3 个的排序变了，D1−F2 = −0.009（p=0.50），在噪声底附近；组内辨别率 4/7 vs F2 5/7，只差一个三元组。
2. 这把今晚的负结果从"文本级干预"扩到"生成目标"：在本基准上，SFD 内容怎么改，BM25 per_query 排序都几乎不动。合理解释是基准分辨力：25 个评测查询的判断池有 6–38 张表（中位 23），其中属于 subset30 的只有 0–4 张（3 个查询为 0、11 个只有 1 张；其余用原描述），改写描述只能移动每池里极少数文档；有共同判断的表对也只有 8 对、7 个有序三元组。
3. 即便邻表选择偷用了 qrels（偏向 D1），仍无增益，所以"辨别式生成在 30 表上有效"这一假设在当前设定下被否定；但不能据此说它在更大子集上无效，因为瓶颈更像是规模而不是方法。
4. 建议：任何新的生成侧方法都先在更大子集（60–100 表，使每池中被改写的表更多）上验证分辨力，或先做一个"oracle 上限"实验（直接把查询词写进相关表描述，看 NDCG 能动多少），确认基准能检测到描述变化后再比方法。两者都需 Mo 批准规模/成本。
